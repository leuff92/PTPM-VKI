# Лабораторная работа 5

**Веселков Лев**

Парсер сообщений учебного форума, хранение данных в SQLite и автоматические тесты.
Задание: [ветка Lab_5](https://github.com/Redsus228/PTPM-VKI/tree/Lab_5).

## Что делает программа

Программа находит ID сообщения, имя автора и содержимое сообщения с HTML-разметкой.
Данные сохраняются в таблицу `comments`. Записи можно получить по ID или автору,
изменить и удалить через класс `DatabaseRepository`.

В проекте используется своя небольшая страница `data/forum.html` — учебная
песочница, разрешённая заданием. Без аргументов программа читает этот файл.
С аргументом `--url` скачивает страницу через `requests`.

Парсер рассчитан на конкретную разметку: `.comment` с атрибутом `data-id`,
внутри которого находятся `.author` и `.message`. Для другого сайта нужно
изменить селекторы. JavaScript программа не выполняет.

## Запуск в PyCharm через Local

Команды ниже предназначены для PowerShell во вкладке **Terminal → Local**.
Откройте папку проекта через **File → Open**. Команды выполняйте в корне проекта,
рядом с `main.py` и `requirements.txt`.

Для нового клона:

```powershell
cd "$env:USERPROFILE\Desktop"
git clone --branch Lab_5 https://github.com/leuff92/PTPM-VKI.git PTPM_Lab5
cd PTPM_Lab5
```

Если репозиторий уже склонирован, перейдите в его папку и выполните:

```powershell
git fetch origin
git checkout Lab_5
git pull --ff-only
```

Подготовка окружения нужна один раз:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если команда `python` не найдена, используйте `py -3 -m venv venv`.
Активировать окружение не требуется: команды явно используют Python из `venv`.
В настройках интерпретатора PyCharm выберите `venv\Scripts\python.exe`.

Запуск:

```powershell
.\venv\Scripts\python.exe main.py
```

При первом запуске появятся строки `Найдено сообщений: 3` и `Добавлено в базу: 3`.
В корне проекта создастся `comments.db`. При повторном запуске новых записей будет
`0`: существующие ID пропускаются. Уже сохранённые сообщения автоматически не
обновляются. Для изменения текста используется `update`.

## Проверка настоящего HTTP-запроса

Откройте **два терминала Local** в корне проекта. В первом запустите сервер:

```powershell
.\venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1 --directory data
```

Оставьте первый терминал работающим. Во втором выполните:

```powershell
.\venv\Scripts\python.exe main.py --url http://127.0.0.1:8000/forum.html
```

Так `requests` действительно загружает HTML по HTTP. Интернет для этой проверки
не нужен. В первом терминале будет виден запрос `GET /forum.html`.
Остановка сервера — **Ctrl+C** в первом терминале.

## Тесты

Все тесты:

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Отдельно база и парсер:

```powershell
.\venv\Scripts\python.exe -m unittest tests.test_database -v
.\venv\Scripts\python.exe -m unittest tests.test_parser -v
```

В проекте **35 тестовых методов**: 23 для базы, 9 для парсера, 3 для запуска.
Ожидаемый итог — `Ran 35 tests` и `OK`. У каждого из пяти обязательных методов
базы есть успешные и отрицательные сценарии. Проверяются также границы длины,
неверные типы, повторные ID и сохранение данных после открытия файла заново.

Тесты не обращаются в интернет: HTML читается из файлов, сетевые вызовы заменяются
через `patch`, а большинство проверок базы используют `:memory:`.

## Правила базы данных

| Поле | Ограничение |
| --- | --- |
| `id` | `INTEGER PRIMARY KEY`, уникальный целочисленный ID |
| `name` | `TEXT NOT NULL`, не более 256 символов |
| `message` | `TEXT NOT NULL`, не более 8096 символов с учётом HTML-тегов |

`add` возвращает `True`. Повторный ID при прямом вызове `add` вызывает
`sqlite3.IntegrityError`. `get_by_id` возвращает словарь или `None`,
`get_by_name` — список словарей. `update` и `delete` возвращают `True`, если запись
найдена, и `False`, если её нет. Неверный тип вызывает `TypeError`, превышение
длины — `ValueError`. Пустая строка допускается: `NOT NULL` запрещает `NULL`,
а не пустой текст.

`sqlite3` и `unittest` входят в стандартную библиотеку Python. Отдельно
устанавливаются `requests`, `beautifulsoup4` и `lxml`. Проверено на Python 3.12.
