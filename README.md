# Лабораторная работа 3

**Автор:** Веселков Лев

**Тема:** интеграционное тестирование и тестовые заглушки

**Проект:** определение типа треугольника

**Ветка:** `Lab_3`

Консольная программа получает три стороны треугольника, определяет его тип
и сохраняет результат в SQLite. При повторном запросе использует готовую
запись из БД. Отправка результата внешнему серверу только имитируется.

Исходные требования преподавателя сохранены без изменений в
[ЗАДАНИЕ_ЛР3.md](ЗАДАНИЕ_ЛР3.md).

## Как работает программа

1. `ConsoleInput` получает три стороны через `input()`.
2. `Controller` ищет запись в SQLite.
3. Если записи нет, `TriangleCalculator` вычисляет результат, а БД сохраняет его.
4. Если запись уже есть, контроллер использует её без повторного вычисления.
5. `SimulatedSender` имитирует отправку строки, после чего контроллер возвращает результат.

Ключ записи — три строки со сторонами в исходном порядке. Пробелы по краям
убираются при вводе. Например, `2, 3, 4` и `4, 3, 2` — разные ключи;
`3` и `3.0` также сохраняются отдельно. Ошибочные данные сохраняются с сообщением
об ошибке. Координаты из предыдущей лабораторной вычисляются, но в БД ЛР3
не записываются.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `lab3/main.py` | Создаёт компоненты, запускает сценарий и закрывает БД |
| `lab3/controller.py` | Управляет вводом, поиском, вычислением, сохранением и отправкой |
| `lab3/calculator.py` | Вызывает метод из предыдущей лабораторной |
| `lab3/triangle.py` | Проверяет стороны, определяет тип и рассчитывает координаты |
| `lab3/database.py` | Методы добавления, получения и удаления записей SQLite |
| `lab3/interfaces.py` | Абстрактные интерфейсы ввода и отправки |
| `lab3/user_input.py` | Консольный ввод |
| `lab3/sender.py` | Имитация отправки без настоящей сети |
| `lab3/tests/` | Компонентные и интеграционные тесты |
| `lab3/verification/` | Результаты проверки и отчёт о покрытии |

Запись SQLite содержит пять полей: три стороны, тип треугольника и сообщение
об ошибке. Файл БД создаётся автоматически в `lab3/data/triangles.sqlite3`.

## Скачивание через Git Bash

Нужны Git и Python 3.10 или новее. Для обычного запуска программы и тестов
сторонние пакеты не требуются.

Создайте пустую папку на рабочем столе, откройте её и нажмите правой кнопкой
по пустому месту → **Open Git Bash here**. Выполните команды по одной:

```bash
git clone --branch Lab_3 https://github.com/leuff92/PTPM-VKI.git .
git branch --show-current
cd lab3
python -m venv venv
```

Точка в конце `git clone` означает клонирование в текущую папку.
Проверка ветки должна вывести `Lab_3`. Папка `lab3` — Python-проект внутри
репозитория, а `Lab_3` — название ветки.

Если репозиторий уже скачан, повторно клонировать его не нужно. Из его корневой
папки выберите ветку командой `git checkout Lab_3`, затем перейдите в `lab3`.
Если окружение `venv` уже создано и работает, повторять его создание не нужно.
Если команда `python` недоступна, попробуйте `py -3 -m venv venv`.

## Запуск в PyCharm

Откройте в PyCharm папку **`lab3`**, а не отдельный файл `main.py`.
Выберите интерпретатор `lab3/venv/Scripts/python.exe`.
Внизу откройте **Terminal → Git Bash** и проверьте текущую папку:

```bash
pwd
ls
```

Если `ls` показывает `main.py`, можно запускать программу. Если открыта корневая
папка репозитория и видна подпапка `lab3`, сначала выполните `cd lab3`.

```bash
./venv/Scripts/python.exe main.py
```

Введите каждую сторону отдельно, нажимая Enter после каждого числа.

| Ввод | Результат |
| --- | --- |
| `2`, `3`, `4` | `разносторонний` |
| `5`, `5`, `5` | `равносторонний` |
| `5`, `5`, `6` | `равнобедренный` |
| `3`, `5`, `2` | Ошибка: стороны не образуют треугольник |
| `abc`, `4`, `5` | Ошибка: стороны должны быть вещественными числами |

При новом запросе появится сообщение «Записи нет: вычисляем результат и сохраняем
в SQLite». При повторном запросе с теми же сторонами в том же порядке —
«Запись найдена: берём готовый результат из SQLite».

Вместо терминала можно открыть `main.py` и выбрать **Run 'main'**.
В этом случае стороны вводятся в окне **Run**. Команды Git Bash вводятся
в **Terminal**, а не в Run или Python Console.

## Проверка тестов

Из папки `lab3` во вкладке Git Bash:

```bash
./venv/Scripts/python.exe -m unittest discover -s tests -v
```

Результат проверки: **31 тест, все проходят**.

```text
Ran 31 tests
OK
```

В `test_integration.py` находятся 17 сценарных проверок, в `test_components.py` —
14 проверок компонентов и точки входа. Первые три интеграционных теста проверяют
новый запрос, получение записи из кэша и повторный запрос. В них работают
настоящие контроллер, калькулятор и SQLite; заглушки заменяют ввод и отправку.
Обёртка калькулятора подсчитывает вызовы, не заменяя настоящее вычисление.

Тесты используют отдельные БД в памяти или временных файлах и не изменяют
рабочую базу данных. Математические юнит-тесты ЛР2 не копировались: здесь
проверяются взаимодействие компонентов и новые части проекта.

утверждениями внутри тестов.
