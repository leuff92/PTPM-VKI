## Восстановленные требования доставки

Непосредственно из исходника: вес от 0.1 до 50 кг включительно, расстояние
от 1 до 5000 км, три вида упаковки. База — 200 рублей плюс 5 рублей/км;
при весе свыше 5 и менее 20 кг коэффициент 1.2, от 20 кг — 1.5.
Хрупкая упаковка добавляет 300 рублей, опасная — 1000 после весового
коэффициента. Дата отправки **фиксирована: 03.09.2026**, как указано в
комментарии исходника. Итоговая стоимость имеет тип `int`.

Принятые при восстановлении бизнес-логики допущения:

- Неполные 500 км требуют округления срока вверх.
- Экспресс — платная дополнительная услуга; его стоимость выше обычной.
  Конкретный коэффициент в требованиях не задан: `2.0` ниже — предложение,
  тесты проверяют только отношение цен.
- Экспресс сокращает срок вдвое с округлением вверх, но минимум до одного дня.
- По аннотациям и описанию функции: вес — конечное число (`int`/`float`,
  кроме `bool`), расстояние — `int`, флаг экспресса — `bool`.
  Неверный ввод возвращает `(-1, "0000-00-00")`, а не выбрасывает исключение.

Результаты, зависящие от восстановленных правил сроков и экспресс-тарифа,
показывают расхождение с этими допущениями, а не с отдельно выданной тарифной
спецификацией. Фиксированная дата и граница 5 кг ошибками не объявлялись.

Предложение для D4 (в начало функции перед нынешней строкой 12):

```python
import math

invalid = (-1, "0000-00-00")
if type(weight) not in (int, float):
    return invalid
if type(distance) is not int or type(is_express) is not bool:
    return invalid
if not (0.1 <= weight <= 50.0 and 1 <= distance <= 5000):
    return invalid
if not math.isfinite(weight):
    return invalid
```

Исходный файл сохранён для воспроизводимости падений. Предложения исправлений
приведены в отчёте; к `Delivery.py` они не применены.

## Исправления своего проекта

- Убрано приближённое сравнение сторон: допуск `abs_tol=1e-12` превращал
  малые разносторонние треугольники в равносторонние, а относительный допуск
  объединял близкие, но различные значения. Теперь сравниваются значения
  `float`, полученные из ввода, без дополнительного допуска.
- Для отсортированных сторон применяется `smallest > largest - middle`:
  малая сторона не теряется при сложении с большой.
- Геометрия строится на самой длинной нормированной стороне, затем вершины
  возвращаются в порядке `AB = A`, `BC = B`, `CA = C`. Это устраняет деление
  на основание, которое может округлиться до нуля. Высота рассчитана через
  устойчивое преобразование формулы Герона.

Растровые координаты округляются до целых в диапазоне 0…100. У крайне тонкого
треугольника точки могут совпасть после округления до пикселей — это ограничение
разрешения, а не основание менять вычисленный тип фигуры.

## Запуск

Python 3.10+. Для программы и тестов внешние библиотеки не нужны.

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m unittest tests.test_triangle -v
.\venv\Scripts\python.exe -m unittest tests.test_delivery -v
.\venv\Scripts\python.exe -m unittest discover -v
```

Треугольники: ожидается `OK`. Исходная доставка и общий запуск: ожидается
`FAILED (failures=15, errors=4)` — эти 19 случаев разобраны в отчёте.
В PyCharm откройте папку проекта, выберите интерпретатор
`venv\Scripts\python.exe`, затем запустите нужный файл тестов через `Run`.

Для обновления протоколов и JSON-статистики:

```powershell
.\venv\Scripts\python.exe scripts/run_checks.py --baseline
.\venv\Scripts\python.exe scripts/run_checks.py
```

Первый запуск использует точную копию кода из ЛР1
`evidence/triangle_lab1.py` (коммит `1d54bae`), второй — исправленный
`triangle.py` и исходный `Delivery.py`. Оба возвращают код 1 при наличии
непройденных тестов. Исходные README и Delivery преподавателя сохранены.
