Проверено 14.10.2026: **31 тест проходит**, покрытие учитываемых строк и
ветвлений прикладного кода — **100%**. Критических ошибок, мешающих выполнению

В проекте есть все требуемые части: калькулятор, SQLite с добавлением,
получением и удалением, ввод через абстрактный интерфейс, имитация отправки
через второй интерфейс и контроллер. Первые три теста в `test_integration.py`
проверяют совместную работу настоящих контроллера, калькулятора и SQLite.
Остальные тесты проверяют новые компоненты и дополнительные сценарии.

Для ЛР3 структура достаточно простая: консольная программа без графического
интерфейса и настоящего сервера. SQLite, `abc` и `unittest` встроены в Python.
Дополнительный пакет `coverage` нужен только для измерения покрытия.
Самая сложная часть — расчёт координат в `triangle.py`, перенесённый из
предыдущей лабораторной. Контроллер ЛР3 использует только тип или ошибку.
Удалять интерфейсы и контроллер не стоит: они прямо требуются заданием.

Сначала разберите вопросы 1–12. Дополнительные вопросы помогут объяснить
отдельные строки кода. Не обязательно учить ответы дословно: важно понимать
порядок действий и уметь показать соответствующее место в проекте.

## Что сказать в начале защиты

«Моя программа определяет тип треугольника по трём сторонам. Контроллер
получает ввод и ищет результат в SQLite. Если записи нет, он вызывает
калькулятор и сохраняет результат. Если запись уже есть, использует её
без повторного вычисления. Затем отправляет строку имитации внешнего сервера
и возвращает результат. В тестах ввод и отправка заменены заглушками».

## Основные вопросы

### 1 Что делает программа

Определяет тип треугольника, сохраняет результат и использует сохранённую
запись при повторном запросе. Если стороны неправильные, возвращает сообщение
об ошибке. Отправка результата на внешний сервер только имитируется.

### 2 Каков порядок работы программы

Ввод трёх сторон → поиск в БД → вычисление и сохранение, если записи нет →
имитация отправки → возврат результата.
Этот порядок записан в `Controller.run()` в `controller.py`.

### 3 Зачем нужен Controller

Он управляет порядком действий. Сам контроллер не читает `input()`,
не выполняет SQL и не рассчитывает координаты: он вызывает другие классы.
Поэтому основная логика находится в одном коротком методе.

### 4 За что отвечает каждый класс

- `ConsoleInput` получает три строки от пользователя.
- `TriangleCalculator` вызывает функцию из предыдущей лабораторной.
- `TriangleDatabase` добавляет, получает и удаляет записи SQLite.
- `SimulatedSender` печатает сообщение, имитируя отправку.
- `Controller` объединяет эти действия в один сценарий.

Объекты этих классов создаются в `main.py`.

### 5 Почему выбрана SQLite

Она встроена в Python и не требует отдельного сервера. При обычном запуске
данные сохраняются в файле `lab3/data/triangles.sqlite3`.
В большинстве тестов используется отдельная БД в памяти.

### 6 Что хранится в одной записи БД

Пять полей: сторона A, сторона B, сторона C, тип треугольника и сообщение
об ошибке. Если ошибки нет, поле сообщения содержит пустую строку.

### 7 Как определяется уникальная запись

По трём введённым сторонам вместе. В SQL это
`PRIMARY KEY (side_a, side_b, side_c)` — составной первичный ключ.
Одинаковая тройка строк не создаёт несколько отдельных записей.

### 8 Что такое кэш и зачем он здесь

Кэш — сохранённый результат, который можно использовать повторно.
При первом запросе результат вычисляется и записывается. При таком же
повторном запросе контроллер берёт его из БД и не вызывает калькулятор.

### 9 Что такое интеграционный тест

Это тест совместной работы нескольких компонентов. Здесь настоящие
контроллер, калькулятор и SQLite работают вместе, а ввод и отправка заменены
заглушками. Обычный компонентный тест проверяет отдельную часть, например
добавление и получение записи в БД.

### 10 Зачем нужны заглушки

Чтобы тест не ждал ручного ввода и не зависел от внешнего сервера.
Заглушка ввода возвращает заранее заданные стороны, а заглушка отправки
позволяет проверить, какая строка была отправлена.
Используется встроенный модуль `unittest.mock`.

### 11 Какие три интеграционных теста показать

Первые три теста в `tests/test_integration.py`:

1. `test_new_request_calculates_stores_and_sends_result` — новый запрос
   вычисляется, сохраняется и отправляется.
2. `test_cached_request_sends_database_result_without_calculating` — готовая
   запись берётся из SQLite, калькулятор не вызывается.
3. `test_second_request_reuses_cache_and_sends_again` — два одинаковых запроса
   дают одно вычисление и две отправки.

Для второго теста важно показать `calculate.assert_not_called()`.
Для третьего — проверку одного вызова калькулятора и двух отправок.

### 12 Почему 31 тест если достаточно пяти

Пять — минимальное количество по заданию, но ещё требуется полное покрытие
написанного кода. Дополнительные тесты проверяют удаление, ошибки, закрытие
БД и другие ветви. Тесты находятся отдельно от программы и не усложняют
пользовательский запуск. Удалять их только ради уменьшения количества не нужно.

## Вопросы по отдельным строкам

### 13 Что такое ABC и abstractmethod

`ABC` — абстрактный базовый класс. `@abstractmethod` отмечает метод, который
наследник должен реализовать. В проекте интерфейсы `UserInput` и `ResultSender`
задают методы `get_sides()` и `send_result()`. Создать объект самого
абстрактного интерфейса нельзя.

### 14 Зачем передавать объекты в конструктор Controller

Контроллер получает готовые ввод, калькулятор, БД и отправитель.
В обычной программе передаются реальные объекты, а в тестах часть из них
можно заменить заглушками, не переписывая `run()`.

### 15 Что означают self и __init__

`self` — текущий объект класса. `__init__` выполняется при его создании.
Например, `self.database = database` сохраняет переданный объект БД,
чтобы затем вызывать его методы внутри контроллера.

### 16 Что делает звёздочка в get(*sides)

Разворачивает кортеж в отдельные аргументы. Если `sides` содержит
`("3", "4", "5")`, вызов `get(*sides)` равнозначен `get("3", "4", "5")`.

### 17 Почему используется record is None

Метод БД `get()` возвращает `None`, если записи нет. Поэтому условие
`if record is None` означает, что нужно вычислить и сохранить результат.
В ветке `else` используется уже найденная запись.

### 18 Почему стороны сначала хранятся как строки

`input()` возвращает строки. Они сохраняются как ключ, в том числе при
ошибочном вводе вроде `abc`. Для проверки треугольника функция переводит
строки в числа через `float()`.

Нюанс: `3` и `3.0` — разные строки и разные ключи БД. Перестановка
`3, 4, 5` в `5, 4, 3` тоже создаёт другой ключ. Тип треугольника остаётся тем же.
Числовая запись и порядок сторон здесь не нормализуются; пробелы по краям
убирает `ConsoleInput` через `.strip()`.

### 19 Что произойдёт при неправильном вводе

Для `abc, 4, 5` получится «Ошибка: Стороны должны быть вещественными числами».
Для `1, 2, 3` получится «Ошибка: Стороны не образуют треугольник».
Ошибочный результат тоже сохраняется и может быть получен повторно из БД.

### 20 Зачем нужны координаты если ЛР3 их не использует

Функция предыдущей лабораторной возвращает тип и координаты.
Калькулятор сохраняет этот формат результата. Контроллер получает оба значения,
но использует только тип. Переменная `_coordinates` показывает, что второе
значение в этом сценарии намеренно не используется. В пяти полях БД координат нет.

Если спросят о формуле: самая длинная сторона берётся за основание,
находится положение третьей вершины и высота, затем координаты масштабируются
в поле 100 на 100 и округляются до целых чисел. Это часть предыдущей лабораторной.

### 21 Зачем нужны вопросительные знаки в SQL

Это места для параметров. Значения передаются отдельно от текста запроса.
Поэтому введённый пользователем текст не становится частью SQL-команды.
Например, `WHERE side_a = ?` получает значение стороны из кортежа параметров.

### 22 Что делают with self.connection и finally

`with self.connection` управляет транзакцией: подтверждает изменения при успехе
и откатывает их при ошибке. Сам по себе этот блок не закрывает соединение.
`finally: database.close()` в `main.py` закрывает соединение и при успешном
выполнении, и при исключении после создания БД.

### 23 Чем Mock отличается от patch и зачем нужен wraps

`Mock` создаёт объект, которым можно заменить зависимость и проверить её вызовы.
`patch` временно заменяет существующий объект, например `builtins.input`.
`return_value` задаёт возвращаемое значение, а `side_effect` — последовательность
значений или исключение.

В `Mock(wraps=TriangleCalculator(), ...)` работает настоящий калькулятор,
а обёртка подсчитывает его вызовы. Это не заглушка математического вычисления.
`create_autospec` создаёт заглушку с методами и сигнатурами заданного интерфейса.

### 24 Что делают setUp и assertEqual

`setUp()` подготавливает объекты перед каждым тестом. Здесь создаётся новая
БД в памяти. `addCleanup(self.database.close)` закрывает её после теста.
`assertEqual` проверяет равенство значений. `assert_called_once_with`
проверяет один вызов с указанными аргументами, а `assert_not_called` — отсутствие вызова.

### 25 Что означает 100 процентов покрытия

При запуске тестов выполнились все учитываемые строки и ветвления
прикладного кода: 147 операторов и 18 ветвлений, пропусков нет.
Это не доказывает отсутствие любых возможных ошибок и не гарантирует оценку.
Само поведение проверяют утверждения внутри тестов.

### 26 Что происходит при сбое БД или отправки

Если чтение или сохранение в БД завершается ошибкой, сценарий прекращается
до отправки. Если отправка падает после сохранения, запись остаётся в БД.
Вызвавший код получает исключение; `main.py` закрывает БД в `finally`.
Учебная программа не превращает все технические сбои в красивые сообщения,
но такое поведение отдельно проверяется тестами.

## Команды для Git Bash в PyCharm

Откройте **Terminal → Git Bash**. Команды выполняйте по одной. Сначала проверьте:

```bash
pwd
ls
```

Нужна папка `lab3`, в которой лежит `main.py`. Если вы в корне репозитория,
выполните `cd lab3`. Если уже внутри `lab3`, повторять эту команду не нужно.

Запуск программы:

```bash
./venv/Scripts/python.exe main.py
```

Введите стороны по одной с Enter. Запуск всех тестов:

```bash
./venv/Scripts/python.exe -m unittest discover -s tests -v
```

Если `coverage` уже установлен в окружении, проверка покрытия:

```bash
./venv/Scripts/python.exe -m coverage run -m unittest discover -s tests -v
./venv/Scripts/python.exe -m coverage report
```

Обычная программа и `unittest` работают без `coverage`.
Подробные установка окружения, клонирование и открытие проекта описаны
в корневой инструкции `ИНСТРУКЦИЯ_ЛР3.md`.
