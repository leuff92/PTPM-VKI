## 1 Что нужно было сделать

Тема работы — сбор данных со страницы и автоматическое тестирование на Python. Нужно получить сообщения из HTML, сохранить их в SQLite и проверить программу через unittest.

По заданию нужны класс DatabaseRepository с пятью методами работы с базой, класс ForumParser и тесты. Для каждого обязательного метода базы требуется минимум два сценария. Для парсера — минимум два теста по сохранённому HTML, без зависимости от интернета.

В этой работе используется учебный форум из файла data/forum.html. В нём три сообщения: два от lev и одно от anna. У каждого сообщения есть ID, автор и текст. Парсер сохраняет внутреннюю HTML-разметку текста.

**Что сказать в начале защиты**

«В этой работе я разбираю HTML учебного форума, получаю сообщения и сохраняю их в SQLite. За базу отвечает DatabaseRepository, за загрузку и разбор страницы — ForumParser. Через unittest проверяются операции с базой, парсер и запуск программы. Сетевые запросы в тестах подменяются, поэтому интернет для тестов не нужен».

| Файл | Что объяснить преподавателю |
| --- | --- |
| main.py | Выбирает источник HTML, вызывает парсер и сохраняет сообщения |
| src/database.py | Создаёт таблицу comments и выполняет пять операций с записями |
| src/parser.py | Скачивает HTML, находит сообщения и передаёт их репозиторию |
| data/forum.html | Учебная страница для демонстрации и проверок |
| tests/test_database.py | Проверяет базу и валидацию данных |
| tests/test_parser.py | Проверяет HTML, HTTP-ошибки и сохранение |
| tests/test_main.py | Проверяет запуск, повторы и обработку ошибок |

Общий путь данных: HTML → ForumParser → список словарей → DatabaseRepository → таблица comments.

## 2 Как подготовить проект и запустить тесты

Открой PyCharm, затем File → Open и выбери папку проекта. Внизу открой Terminal и вкладку Local. Вводи команды по одной, без символа доллара в начале строки.

Если проект уже есть на компьютере, перейди в его папку. Для твоего прежнего расположения команда такая:

```powershell
cd "C:\Users\Super PC\Desktop\1\PTPM-VKI"
git fetch origin
git checkout Lab_5
git pull --ff-only
```

Команда переключения ветки начинается с git. Если Git сообщает о несохранённых изменениях, сначала разберись с ними; не используй принудительное переключение.

Окружение и библиотеки подготавливаются один раз:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если python не найден, вместо первой команды выполни py -3 -m venv venv. Активация окружения не нужна, потому что дальше указан полный путь к его Python.

Запуск программы:

```powershell
.\venv\Scripts\python.exe main.py
```

Запуск всех тестов:

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Ожидаемый итог: Ran 35 tests и OK. Для проверки только базы выполни:

```powershell
.\venv\Scripts\python.exe -m unittest tests.test_database -v
```

Если написано No module named requests, установи requirements.txt командой выше. Если tests не найдена, проверь папку командой dir: рядом должны быть main.py, src и tests.

## 3 Как показать работу приложения

Без аргументов main.py читает data/forum.html. Первый запуск с новой базой выводит Найдено сообщений: 3 и Добавлено в базу: 3. Затем появляются ID, автор и HTML каждого сообщения. В корне проекта создаётся comments.db.

Повторный запуск с той же базой выводит Добавлено в базу: 0. Это означает, что уже сохранённые ID пропущены. Старый текст автоматически не заменяется: для изменения предусмотрен метод update.

Чтобы отдельно показать загрузку по HTTP, открой два терминала Local в корне проекта. В первом выполни:

```powershell

```powershell
.\venv\Scripts\python.exe main.py --url http://127.0.0.1:8000/forum.html

Интернет для такой демонстрации не нужен. Сервер останавливается сочетанием Ctrl+C в первом терминале.

Для отдельной новой базы можно указать другое имя:

## 4 Вопросы по коду базы данных

**1. Для чего нужен DatabaseRepository?**
Он хранит SQL-запросы и даёт остальному коду простые методы. Парсеру не нужно самостоятельно выполнять SQL.

**2. Что происходит в конструкторе __init__?**
Создаётся соединение с SQLite, задаётся sqlite3.Row и создаётся таблица comments, если её ещё нет. commit завершает изменения. CREATE TABLE IF NOT EXISTS сохраняет уже существующую таблицу.

**3. Какие поля есть в comments?**
id — INTEGER PRIMARY KEY; name — TEXT NOT NULL до 256 символов; message — TEXT NOT NULL до 8096 символов. HTML-теги входят в длину message. Пустой текст допустим: NOT NULL запрещает значение NULL.

**4. Что возвращают пять обязательных методов?**
add — True при успехе. get_by_id — словарь с полями id, name, message или None. get_by_name — список словарей, включая пустой список при отсутствии записей. update и delete — True при найденной записи, иначе False.

**5. Зачем нужны _check_id и _check_text?**
Они проверяют данные перед SQL-запросом. ID должен быть int, имя и текст — str. Длина строк не должна превышать предел. type(value) is int также не пропускает True и False, которые в Python являются подклассом int.

**6. Какие ошибки могут возникнуть?**
TypeError означает неверный тип, ValueError — превышение длины. sqlite3.IntegrityError возникает при повторном ID в add. Сам репозиторий не скрывает эти ошибки; main выводит понятное сообщение.

**7. Что означают вопросительные знаки в SQL?**
Это места для параметров. Значения передаются отдельно, поэтому кавычки внутри имени остаются данными и не становятся частью команды. Кортеж с одним элементом записывается с запятой: (comment_id,).

**8. Для чего нужны with self.connection и close?**
with завершает транзакцию после успешного изменения или откатывает её при ошибке. Соединение этот блок не закрывает. close закрывает его отдельно; в main вызов находится в finally, чтобы выполниться и при ошибке.

**9. Зачем sqlite3.Row, fetchone и fetchall?**
Row позволяет обращаться к столбцам по именам. fetchone получает одну строку или None, fetchall — список строк. dict(row) превращает строку базы в обычный словарь Python.

## 5 Вопросы по коду парсера и запуска

**10. Чем отличаются parse_page и parse_html?**
parse_page получает страницу через requests и передаёт её в parse_html. parse_html разбирает уже готовый HTML. Такое разделение позволяет проверять разбор без сети.

**11. Какие данные отправляет requests.get?**
Адрес страницы, заголовок User-Agent со значением Lab5ForumParser/1.0 и timeout=10. User-Agent представляет клиент серверу, но не гарантирует доступ к любому сайту. Timeout ограничивает ожидание сетевых операций, а не общее время всей программы.

**12. Зачем raise_for_status и response.content?**
raise_for_status вызывает HTTPError при статусах 4xx или 5xx. content содержит байты HTML; BeautifulSoup может определить кодировку по метаданным страницы. У учебной страницы явно указан UTF-8.

**13. Что делают BeautifulSoup и lxml?**
BeautifulSoup даёт удобные методы поиска по HTML. lxml — выбранный движок, который строит дерево документа. Вызов BeautifulSoup(html, "lxml") объединяет эти две части.

**14. Как находятся сообщения?**
select(".comment") находит блоки с классом comment. select_one(".author") и select_one(".message") находят автора и текст внутри каждого блока. block.get("data-id", "") получает ID, затем int превращает его в число.

**15. Почему автор читается через get_text, а сообщение через decode_contents?**
У автора нужен обычный текст без окружающего тега. У сообщения нужно сохранить внутренние теги, например <p> и <b>. strip убирает пробелы по краям строки.

**16. Что происходит с неполным сообщением или другой страницей?**
Блок без автора, текста или числового ID пропускается через continue. Если подходящих блоков нет, возвращается пустой список. Парсер рассчитан на разметку учебного форума; для другого сайта нужны его селекторы. JavaScript не выполняется.

**17. Что делает save_to_db?**
Обходит список сообщений. Если get_by_id возвращает None, вызывает add и увеличивает счётчик. При уже известном ID пропускает запись. Возвращает количество добавленных сообщений.

**18. Для чего нужны argparse и if __name__ == "__main__"?**
argparse читает параметры --url и --db. Условие в конце main.py запускает программу только при непосредственном выполнении файла. При импорте в тесты запуск не происходит. Код завершения 0 означает успех, 1 — обработанную ошибку.

## 6 Вопросы по тестам

**19. Что проверяют тесты и сколько их?**
Есть 35 тестовых методов: 23 для базы, 9 для парсера, 3 для запуска. У всех пяти методов базы есть минимум два сценария. Проверяются результаты, ошибки, длины строк, дубли и сохранение данных в файле.

**20. Для чего нужны setUp и tearDown?**
setUp выполняется перед каждым тестом базы и создаёт новое соединение. tearDown выполняется после теста и закрывает его. Благодаря новой базе тесты не зависят от результатов друг друга.

**21. Что означает строка :memory:?**
SQLite создаёт временную базу в оперативной памяти вместо файла на диске. После закрытия соединения она исчезает. Сохранение на диск отдельно проверяется тестом test_file_persistence с временной папкой.

**22. Какие проверки выполняют assertEqual и assertRaises?**
assertEqual сравнивает фактический и ожидаемый результат. assertRaises проверяет, что операция вызвала нужное исключение. assertTrue, assertFalse и assertIsNone проверяют True, False и None соответственно.

**23. Что такое положительный и отрицательный сценарии?**
Положительный: правильная запись добавляется и читается. Отрицательный: повторный ID вызывает IntegrityError или слишком длинное сообщение вызывает ValueError. Отрицательный сценарий считается успешным тестом, если ожидаемая ошибка получена.

**24. Что такое граничные значения?**
Это значения у предела допустимого диапазона. В работе имя из 256 символов и текст из 8096 принимаются, а 257 и 8097 отклоняются. Для update проверяется сохранение старого текста после неправильного обновления.

**25. Что делают patch и Mock?**
patch временно заменяет requests.get по пути src.parser.requests.get. Подмена возвращает подготовленный HTML или вызывает нужную сетевую ошибку. Mock позволяет задать поведение объекта и проверить вызовы. После теста patch восстанавливает исходную функцию.

**26. Что такое фикстура и зачем второй HTML-файл?**
Фикстура — заранее подготовленные данные для проверки. Основная страница содержит правильные сообщения; invalid_forum.html содержит неполные блоки и неправильный ID. Эти файлы позволяют точно сравнить ожидаемый результат с полученным.

**27. Как запускаются тесты и что означает OK?**
unittest discover ищет файлы test*.py в tests и выполняет методы test_ в классах TestCase. -s указывает папку, -v включает подробный вывод. OK означает, что все выполненные проверки прошли; это не доказательство отсутствия любых возможных ошибок.
