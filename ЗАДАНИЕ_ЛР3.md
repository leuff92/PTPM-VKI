---

## 📅 Порядок выполнения и сдачи работы

1. Создать проект на Python, включающий структуру классов и логику взаимодействия, описанную в требованиях ниже.
2. Написать для разработанного проекта **не менее 5 тестов** с использованием встроенной библиотеки `unittest`.
    > ⚠️ **Важно:** Минимум 3 из этих тестов должны быть интеграционными. Остальные тесты не должны дублировать проверки, которые вы уже реализовали в Лабораторной работе №2. Весь написанный код должен быть полностью покрыт тестами. При проверке изоляции модулей обязательно использовать тестовые заглушки (для имитации пользовательского ввода и отправки данных на внешний сервер).
3. В ветку третьей лабы закомитить весь код и тесты и запушить на свой удалённый репозиторий. .
4. Сдать задание мастеру практики.

## 🛠 Стек технологий
* **Язык программирования:** Python 3.x
* **Инструмент тестирования:** Встроенный модуль `unittest.mock` (стандартная библиотека Python)
* **База данных:** SQLite (встроенный модуль `sqlite3`) или любая другая БД на выбор.

## 📐 Архитектура проекта и требования к классам

В результате выполнения задания у вас должна получиться программа с классами (модулями), которые взаимодействуют друг с другом в рамках объединяющего класса-контроллера (`Controller`), реализующего бизнес-логику.

Вам необходимо создать проект, включающий следующие классы:

### a. Класс вычислений / валидации
Класс с одним методом, который был реализован в задании «Лабораторная работа №1».

### b. Класс работы с базой данных
Класс, реализующий методы работы с базой данных (БД — любая на выбор, рекомендуется SQLite). В классе реализовать метод добавления данных, метод получения данных, метод удаления данных.
* **Для проекта «Треугольник»** одна запись БД содержит данные: `длина1`, `длина2`, `длина3`, `тип_треугольника`, `сообщение_об_ошибке` *(если она есть)*; каждая запись идентифицируется по заданным трем длинам сторон.
* **Для проекта «Регистрация»** одна запись БД содержит данные: `логин`, `пароль`, `подтверждение_пароля`, `результат_авторизации`, `сообщение_об_ошибке` *(если она есть)*; каждая запись идентифицируется по логину, паролю и подтверждению пароля.

### c. Класс взаимодействия с пользователем
Класс, реализующий взаимодействие с пользователем: в классе реализовать метод получения информации от пользователя (через консоль с помощью функций ввода `input()` или через графический интерфейс с использованием Tkinter, как вариант, если хотите усложнить себе задачу). Класс написать путем реализации абстрактного базового класса (модуль `abc`), выступающего в роли интерфейса.

### d. Класс сторонней зависимости
Класс, реализующий метод для имитации взаимодействия со сторонней зависимостью (передачи данных стороннему процессу, например, email-серверу). Класс написать путем реализации абстрактного базового класса, выступающего в роли интерфейса. Внутри класса реализуется исключительно имитация передачи данных.

### e. Класс-контроллер (Controller)
Класс (`Controller`), реализующий бизнес-логику сквозного сценария:
1. У пользователя запрашиваются входные данные (через класс взаимодействия).
2. Осуществляется проверка: если для данных нет записи в БД \(\rightarrow\) вычисляется результат (через класс вычислений) и добавляется запись в БД; если для данных есть запись в БД \(\rightarrow\) результат берется из БД.
3. Осуществляется отправка строки-результата сторонней зависимости (через класс сторонней зависимости).
4. Метод возвращает результат выполнения операции.
