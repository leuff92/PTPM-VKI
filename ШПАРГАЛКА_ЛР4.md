# Шпаргалка по лабораторной работе 4

Веселков Лев. Юнит-тестирование класса Converter.

Эта работа проверяет условия, отбрасывание дробной части и умение писать
юнит-тесты. Главное на защите — объяснить пять диапазонов, ноль и граничные
значения. База данных и сложная архитектура из ЛР3 здесь не нужны.

## 1. Алгоритм и код

На входе float с одним знаком после точки. На выходе int, кроме нуля:
для нулевого входа метод вызывает ValueError.

| Входное значение | Действие |
| --- | --- |
| x >= 100.7 | вернуть 1000 |
| 0 < x < 100.7 | вернуть int(x) |
| x == 0.0 | вызвать ValueError |
| -30.4 <= x < 0 | вернуть int(x) - 5 |
| x <= -30.5 | вернуть -2000 |

Основная логика метода без поясняющих комментариев:

```python
class Converter:
    @staticmethod
    def do(x: float) -> int:
        if x >= 100.7:
            return 1000
        if x > 0:
            return int(x)
        if x == 0:
            raise ValueError(
                "Число x не должно быть равно нулю."
            )
        if x >= -30.4:
            return int(x) - 5
        return -2000
```

`return` сразу завершает метод. Поэтому после проверки нуля последующие
условия рассматривают только отрицательные числа.
При входе с одним десятичным знаком все оставшиеся в последней строке числа
не больше -30.5. Дополнительная проверка там не нужна.

Что сказать в начале: «Я реализовал статический метод Converter.do.
Он выбирает одно из пяти правил по значению числа. Проверил обычные значения,
границы диапазонов, тип результата и исключение для нуля с помощью unittest».

## 2. Вопросы по коду

**1. Что означает @staticmethod?**

Метод не получает self и не использует состояние объекта. Его можно вызвать
через класс: `Converter.do(65.7)`. Создавать объект для этого не требуется.

**2. Зачем сначала проверять x >= 100.7?**

Эти числа тоже положительные. Если сначала написать `if x > 0`, число 100.7
попадёт под int(x) и даст 100 вместо положенных 1000.

**3. Что делает int(x)?**

Отбрасывает дробную часть к нулю, а не округляет до ближайшего целого.
`int(65.7)` даёт 65, `int(-1.9)` даёт -1.

**4. Почему для -1.9 ответ -6, а не -7?**

Сначала получается int(-1.9), то есть -1. Затем вычитается 5: ответ -6.
Округление вниз до -2 здесь использовать нельзя.

**5. Что получится для 0.1 и -0.1?**

Для 0.1 получится 0. Для -0.1 получится -5: int(-0.1) равен 0, затем минус 5.
Нулевой результат допустим; исключение требуется только при нулевом входе.

**6. Что происходит на верхней границе?**

Для 100.6 результат 100. Для 100.7 уже 1000: граница включена в верхний диапазон.
Пара значений проверяет правильность знака >=.

**7. Что происходит на отрицательной границе?**

Для -30.4 результат -35. Для -30.5 результат -2000. Оба числа — включённые
границы своих диапазонов, их обязательно нужно проверить.

**8. Что происходит при 0.0 и -0.0?**

В обоих случаях вызывается ValueError: при сравнении с нулём эти значения равны.
Метод не должен возвращать для них число или строку ошибки.

**9. А если передать -30.45 или NaN?**

Это вне указанного формата входа: по заданию число имеет один знак после точки.
Между -30.5 и -30.4 нет допустимого значения такого формата. Дополнительные
правила для NaN, бесконечностей и лишних десятичных знаков здесь не придумывались.

## 3. Вопросы по тестам и защита

**10. Что такое unittest?**

Встроенный модуль Python для автоматических тестов. Класс тестов наследует
unittest.TestCase, а названия проверок начинаются с test_.

**11. Чем юнит-тест отличается от интеграционного?**

Юнит-тест проверяет отдельную часть, здесь Converter.do. Интеграционный
проверяет взаимодействие компонентов. Для проверки Converter не нужны БД и сервер.

**12. Что проверяет assertEqual?**

Сравнивает фактический и ожидаемый результат, например:
`self.assertEqual(Converter.do(65.7), 65)`.

**13. Как проверить ValueError?**

Вызвать метод внутри assertRaises. Тест пройдёт, если возникнет нужное исключение:

```python
with self.assertRaises(ValueError):
    Converter.do(0.0)
```

**14. Для чего нужен subTest?**

Позволяет проверить несколько примеров в одном методе теста. Если один пример
не проходит, в отчёте видно его x, а цикл продолжает проверять остальные.

**15. Какие тесты есть в проекте?**

Всего 10 методов: 6 проверяют диапазоны, границы, ноль и тип int; ещё 4 проверяют
консольный запуск. Внутри используются подтесты с несколькими входными значениями.

**16. Что означает 100 процентов покрытия?**

При проверке выполнены все 21 учитываемый оператор и 10 ветвлений программы.
Это не гарантирует отсутствие любых ошибок: ожидаемые ответы проверяют assert-ы.

**17. Почему main показывает ошибку, а Converter вызывает исключение?**

Так разделены обязанности: Converter сообщает о нуле через ValueError,
а main перехватывает исключение и печатает его пользователю без traceback.

**18. Что показать преподавателю?**

Открой converter.py, объясни порядок условий. Покажи пары 100.6/100.7 и
-30.4/-30.5, отдельно assertRaises для нуля. Затем запусти все тесты.

В PyCharm открой **Terminal → Git Bash** в папке проекта:

```bash
./venv/Scripts/python.exe main.py
./venv/Scripts/python.exe -m unittest discover -s tests -v
```

Выполняй по одной команде. Если venv ещё нет, сначала создай его:
`python -m venv venv`. Ожидаемый результат тестов: **Ran 10 tests**, **OK**.
