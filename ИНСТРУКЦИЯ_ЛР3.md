# Лабораторная работа 3 — запуск и объяснение

Автор: Веселков Лев. Проект: `leuff92/PTPM-VKI`, ветка `Lab_3`.

Все команды ниже предназначены для **Git Bash в Windows**. Сначала используйте
**Open Git Bash here** в папке на рабочем столе, затем вкладку **Git Bash**
в терминале PyCharm. Выполняйте команды по одной, нажимая Enter.
`git cope` — это `git clone`: создание локальной копии репозитория.
Ветка `Lab_3` — версия репозитория, а папка `lab3` — сам Python-проект внутри неё.
Не копируйте символ `$` из приглашения терминала. В путях Git Bash используйте
прямые слеши `/`; пути с пробелами заключайте в кавычки.

## 1. Создать папку и открыть Git Bash

1. На рабочем столе нажмите правой кнопкой мыши по пустому месту.
2. Выберите **Создать → Папку** и назовите её `PTPM_Lab3`.
3. Откройте эту папку. Для нового клонирования она должна быть пустой.
4. Нажмите правой кнопкой по пустому месту внутри папки и выберите
   **Open Git Bash here**. В Windows 11 пункт может находиться в
   **Показать дополнительные параметры**.
5. Откроется Git Bash. Команды из следующих разделов вводите в это окно.

Папка `PTPM_Lab3` на вашем ПК уже содержит готовый проект: её повторно создавать
и клонировать не нужно. Для неё используйте раздел 9. Если нужна новая копия
для демонстрации преподавателю, создайте другую пустую папку, например
`PTPM_Lab3_demo`, и выполните разделы 2–8 в ней.

## 2. Проверить Git и Python

В открытом через **Open Git Bash here** окне выполните:

```bash
pwd
ls
git --version
python --version
```

`pwd` показывает текущую папку, `ls` — её содержимое. Перед новым клонированием
вы должны находиться в созданной пустой папке. Команды проверки версий должны
вывести версии Git и Python. Нужен Python **3.10 или новее**.
Если `python` не найден, попробуйте `py --version`; далее можно заменить
`python -m venv venv` на `py -3 -m venv venv`.
Если нет ни Python, ни Git, сначала установите их с официальных сайтов
[Python](https://www.python.org/downloads/windows/) и
[Git](https://git-scm.com/download/win), затем заново откройте Git Bash.

## 3. Скопировать репозиторий и выбрать третью лабораторную

```bash
git clone --branch Lab_3 https://github.com/leuff92/PTPM-VKI.git .
git branch --show-current
ls
```

`--branch Lab_3` сразу выбирает нужную ветку. Точка в конце означает
«клонировать в текущую папку», поэтому дополнительная папка `PTPM-VKI`
не создаётся. Проверка ветки должна вывести `Lab_3`.
В списке файлов найдите `README.md`, эту инструкцию и папку `lab3`.

## 4. Найти проект и создать окружение

```bash
cd lab3
pwd
ls
python -m venv venv
./venv/Scripts/python.exe --version
```

Теперь текущая папка — `PTPM_Lab3\lab3`. В ней есть `main.py`, `controller.py`,
`database.py`, папка `tests` и подсказки. `venv` — отдельный интерпретатор проекта.
Для работы программы и `unittest` ничего устанавливать через pip не нужно.
Команды с `./venv/Scripts/python.exe` работают без активации окружения.
Если `venv` уже существует и интерпретатор работает, создавать его заново не нужно.

## 5. Запустить программу и тесты из консоли

```bash
./venv/Scripts/python.exe main.py
```

Введите три стороны, каждую с новой строки: `3`, `4`, `5`.
Будет выведен тип `разносторонний`, сообщение о сохранении в SQLite,
имитация отправки и итоговый результат. Файл БД создастся автоматически:
`lab3\data\triangles.sqlite3`.

Повторите команду и введите ту же тройку. Теперь сообщение покажет, что результат
получен из SQLite. Если эти данные уже были сохранены раньше, кэш используется
сразу. Ошибочные значения, например `1`, `2`, `3` или `abc`, `4`, `5`,
дают понятное сообщение об ошибке.

Запустить все тесты:

```bash
./venv/Scripts/python.exe -m unittest discover -s tests -v
```

Ожидаемый итог:

```text
Ran 31 tests
OK
```

Запустить отдельно сквозные сценарии:

```bash
./venv/Scripts/python.exe -m unittest tests.test_integration -v
```

Эта команда запускает 17 проверок. Минимум три полноценные интеграционные
проверки: новый запрос, получение кэша и повторный запрос. В них реальные
контроллер, калькулятор и SQLite, а ввод и отправка заменены заглушками.
Тесты не изменяют рабочую БД: используются отдельные БД в памяти и временный файл.

## 6. Открыть проект в PyCharm

Откройте PyCharm через ярлык Windows или меню «Пуск». Выберите **Open / Открыть**
на стартовом экране либо **File → Open** в уже открытой IDE. Укажите папку
`PTPM_Lab3\lab3`, а не отдельный файл `main.py`. При выборе окна нажмите
**New Window**, чтобы не закрывать другой проект.

Если нужна команда открытия из обычного Git Bash, оставаясь в `lab3`, выполните:

```bash
"/c/Program Files/JetBrains/PyCharm 2025.1.1.1/bin/pycharm64.exe" .
```

`/c/` обозначает диск C, кавычки нужны из-за пробелов, точка передаёт текущую
папку как проект. На другом ПК путь зависит от установленной версии PyCharm.
Если появляется **Start Failed**, используйте запуск через ярлык Windows.
Если IDE предлагает доверять проекту, подтвердите доверие только после проверки,
что открыта ваша папка `PTPM_Lab3\lab3`.

## 7. Запустить в PyCharm через Git Bash

1. Откройте **File → Settings** (`Ctrl+Alt+S`). Найдите страницу
   **Python Interpreter**, при необходимости через поиск настроек.
2. Выберите **Add Interpreter → Add Local Interpreter**.
3. Укажите существующее окружение (**Existing / Select existing**),
   путь к интерпретатору: `PTPM_Lab3\lab3\venv\Scripts\python.exe`.
4. Нажмите **OK / Apply**. Дождитесь завершения индексации проекта.
5. Откройте нижнюю панель **Terminal** (`Alt+F12`). Нажмите вкладку **Git Bash**,
   как на вашем скриншоте. Если её нет, нажмите стрелку рядом с `+` и выберите
   **Git Bash** из списка доступных оболочек.
6. Если Git Bash отсутствует в списке, откройте **File → Settings → Tools → Terminal**.
   В поле **Shell path** укажите `"C:\Program Files\Git\bin\bash.exe" --login -i`.
   Примените настройку и создайте новую вкладку терминала кнопкой `+`.
   На другом ПК путь к `bash.exe` может отличаться.

Во вкладке **Git Bash** проверьте папку:

```bash
pwd
ls
```

Если `pwd` оканчивается на `/lab3` и `ls` показывает `main.py`, вы уже на месте.
Если открыта корневая папка репозитория и `ls` показывает подпапку `lab3`,
выполните `cd lab3`. Не вводите `cd lab3` второй раз из самой папки `lab3`.
Теперь запустите программу прямо в этом терминале:

```bash
./venv/Scripts/python.exe main.py
```

Введите `3`, затем Enter, `4`, Enter, `5`, Enter. Дождитесь результата и
возвращения приглашения Git Bash. Затем в той же вкладке запустите тесты:

```bash
./venv/Scripts/python.exe -m unittest discover -s tests -v
```

Это те же команды, что и в отдельном окне Git Bash. Для запуска кнопкой IDE
откройте `main.py`, нажмите правой кнопкой по редактору и выберите **Run 'main'**;
в таком случае стороны вводятся в окне **Run**, а не в **Terminal**.
Активация окружения необязательна. Если хотите её использовать в Git Bash,
выполните `source venv/Scripts/activate`; после этого можно писать `python main.py`.

Если в конфигурации запуска задана рабочая папка, укажите `PTPM_Lab3\lab3`.
При запуске через `main.py` путь к SQLite определяется от самого файла,
поэтому данные остаются в `lab3\data`.

Это необязательный инструмент для проверки требования «весь код покрыт тестами».
Из папки `lab3`:

```bash
./venv/Scripts/python.exe -m pip install -r requirements-dev.txt
```

## 9. Повторное открытие или обновление проекта

Если папка уже создана, повторно клонировать не нужно. Откройте `PTPM_Lab3`
в Проводнике, нажмите правой кнопкой по пустому месту и выберите
**Open Git Bash here**. Сначала проверьте состояние и текущую ветку:

```bash
git status
git branch --show-current
```

Продолжайте только если рабочее дерево чистое и текущая ветка — `Lab_3`:

```bash
git pull --ff-only
cd lab3
```

`git pull --ff-only` обновляет текущую ветку без создания автоматического
коммита слияния. Выполняйте обновление только если `git status` показывает чистое
рабочее дерево и текущая ветка — `Lab_3`. Иначе сначала разберитесь с изменениями
или выберите нужную ветку. Откройте проект в PyCharm по разделу 6 и продолжайте
во вкладке **Git Bash**. Для выбора ЛР3 в уже существующем чистом репозитории:

```bash
git fetch origin
git switch Lab_3
git branch --show-current
```

Выполняйте Git-команды внутри репозитория; в `lab3` Git также найдёт его корень.

## 10. Как сохранить свои изменения и отправить в GitHub

В **Terminal → Git Bash**, находясь в `lab3`, перейдите на уровень выше:

```bash
cd ..
git branch --show-current
git status
git config user.name 'Веселков Лев'
git config user.email 'veselkovlev92@gmail.com'
git add lab3
git diff --cached
git commit -m 'Update Lab 3'
git push origin Lab_3
```

Перед коммитом убедитесь, что текущая ветка — `Lab_3`.
`git add` выбирает изменения, `git commit` сохраняет их локально, `git push`
передаёт коммиты на GitHub. Файл `.gitignore` исключает окружение, БД и кэши.
Если файлы не менялись, Git сообщит `nothing to commit` — это нормально.
При запросе авторизации используйте свою учётную запись GitHub.

## 11. Что объяснить преподавателю

Основной код — `controller.py`. Последовательность:
ввод → поиск в SQLite → вычисление при отсутствии записи → сохранение →
имитация отправки → возврат строки.

| Файл | Что показать |
| --- | --- |
| `main.py` | Сборку компонентов и закрытие БД в `finally` |
| `controller.py` | Условие `if record is None` и сквозной сценарий |
| `database.py` | `add`, `get`, `delete`, составной ключ и параметры SQL `?` |
| `interfaces.py` | Два абстрактных интерфейса на основе `ABC` |
| `user_input.py` | Реализацию `get_sides` через `input()` |
| `sender.py` | Имитацию отправки строки |
| `calculator.py` | Обёртку над методом предыдущей лабораторной |
| `tests/test_integration.py` | Новый запрос, кэш, повтор и подмену внешних зависимостей |

Краткое объяснение и ответы на вопросы — в `lab3/ПОДСКАЗКИ.md`.
Ошибочные данные тоже сохраняются. Ключом служат три строки в исходном
порядке, без нормализации числовой записи. Координаты старого метода
не входят в пять полей БД и отправляемую строку.

## 12. Частые проблемы

**`fatal: destination path '.' already exists and is not an empty directory`.**
Вы пытаетесь клонировать в непустую папку. Используйте существующую копию
по разделу 9 или создайте другую пустую папку.

**`fatal: not a git repository`.** Вы находитесь вне склонированной папки.
Откройте Git Bash заново через **Open Git Bash here** внутри `PTPM_Lab3`.

**`can't open file main.py`.** Найдите папку командой `ls`, затем
перейдите в неё командой `cd lab3`. Проверьте `pwd`.

**`Ran 0 tests`.** Вы запускаете поиск не из той папки. Перейдите в `lab3`
и используйте `-m unittest discover -s tests -v`.

**`No module named coverage`.** Для обычного запуска тестов coverage не нужна.
Для измерения покрытия выполните установку из раздела 8.

**PyCharm показывает `No interpreter`.** Выберите существующий
`lab3\venv\Scripts\python.exe` по разделу 7.

**`./venv/Scripts/python.exe: No such file or directory`.** Проверьте `pwd` и `ls`.
Нужно находиться в `lab3`; если окружение отсутствует, создайте его командой
`python -m venv venv`. В Git Bash пишите `/`, а не `\`.

**Открылась вкладка Local с другой оболочкой.** Переключитесь на вкладку **Git Bash**.
Название вкладки само по себе не меняет оболочку; при необходимости настройте
**Shell path** по разделу 7 и откройте новую вкладку.

**PyCharm не найден по указанному пути.** Путь зависит от установленной версии.
Откройте программу через «Пуск» и выберите **Open**.

**PyCharm показывает Start Failed и ошибку `.port`.** На вашем ПК такая ошибка
возникала при запуске из Codex. Откройте PyCharm обычным ярлыком Windows,
затем выберите **File → Open → PTPM_Lab3\lab3**. Не нажимайте
**Reset Settings & Plugins** для обычного открытия проекта.
